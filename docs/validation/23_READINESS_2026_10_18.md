## What changed

### Decisions and slide matching

`require_final_decision=True` now really requires an explicit decision event. A decision anchor already consumed by a prior cluster cannot create another confirmed decision outside its cluster. Generic agreement hours later cannot resolve an unrelated earlier proposal. Default candidate-oriented behavior remains available.

Slide timing contributes to a weighted score instead of acting as an absolute veto on semantic candidates. Semantic-only comparison therefore genuinely ignores timing. Temporal-only alignment can run without an embedding model or weights. Derived alignment JSONs record the actual weights, threshold, model and top-k settings.

### Evaluation integrity

- Speaking-time baselines use complete saved transcript intervals, including speech without extracted events. Same-speaker overlapping intervals are unioned; adjacent passages stay one turn until a speaker change, unknown interval or gap over 0.5 seconds. This is a disclosed baseline convention, not a validated conversational-turn model.
- Baselines use the complete known participant set when a transcript is supplied. UNKNOWN is not treated as an identified participant. Legacy callers without a transcript retain an explicitly labelled `event_duration_proxy`.
- The no-PPT baseline retains speech and recomputes evidence/decisions after removing slide links. It no longer discards events just because they were grounded in a slide.
- A1 reruns the current full downstream control; A2 removes PPT; A3 realigns semantic-only; A4 realigns temporal-only. Evidence, decisions, interactions and influence are recomputed from their own inputs. A5–A7 are explicitly feature-weight ablations. A8 is the speaking-time baseline. Missing required variant inputs are marked unavailable rather than assigned misleading scores.
- Equal influence scores retain tied ranks. Pure-Python Spearman/Kendall fallbacks handle ties correctly; constant ranks produce undefined metrics, not NaN JSON or invented correlations.
- Events/decisions use maximum one-to-one matching so file order cannot change true-positive counts. Known event speakers must agree. Decision matching requires all comparable supplied topic/time fields; missing times are not silently converted to zero, and empty topics cannot match each other. This is **matching protocol v2** and must be used consistently when comparing methods or rescoring historical results. Status classification/semantic entailment still require a separate labelled protocol.

Main files: `src/meeting/decisions.py`, `src/meeting/influence.py`, `src/fusion/multimodal_representation.py`, `src/evaluation/{metrics,baselines,ablation}.py`, `scripts/run_evaluation.py`, and regression tests.

### Optional image-slide OCR

`src/ppt/ocr.py` uses the already installed Tesseract binary through a bounded, timed subprocess. It checks byte/pixel limits, handles transparent backgrounds, performs no network access and does not fabricate confidence values. `PPTXExtractor` reads embedded/grouped pictures when enabled; OCR provenance remains in slide metadata and recognized text reaches embedding/matching/report paths. The browser identifies OCR-bearing slides.

Only OCR weights were downloaded: English **4,113,088 bytes** and Hindi **1,122,751 bytes**, plus their license. Source: [official tessdata_fast repository](https://github.com/tesseract-ocr/tessdata_fast), pinned revision `87416418657359cb625c412a48b6e1d6d41c29bd`, Apache-2.0. Provisioning verifies pinned Git blob hashes and records SHA-256 hashes in `models/tesseract/manifest.json`. [Tesseract's command documentation](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html) describes the local CLI. No Python or system packages were installed; Pillow was already present and is now an explicit requirement.

`ppt.ocr_enabled` remains `false` by default. Enable it using the [current guide](../guides/RUN_CURRENT.md). OCR reads text, not diagrams/visual semantics, and the Tesseract implementation is laptop-only.

### Android memory and model handling

`ModelFile.java` validates multilingual GGML headers, vocabulary boundaries, tensor block sizes, uniqueness/counts and complete payloads before model replacement. The real base model passes; magic-only files, invalid headers and truncated tensors are rejected. This checks structural completeness, not authenticity or recognition quality. Common F32/F16/Q4/Q5/Q8 and K-block layouts are supported; unsupported formats are explicitly rejected.

`SpeakerBudget.java` reserves at most one quarter of currently available system memory for the PCM float buffer, capped at **512 MiB**. Low-memory state disables fresh speaker inference. The native layer independently enforces the allocation ceiling. A device with sufficient available memory can admit roughly **139 minutes** instead of the previous fixed hour. This is a maximum input-buffer allowance, not a guaranteed total-process memory bound, speed or battery result. Global clustering is retained; independent chunk identities are not silently stitched together. Compatible cached speaker turns can be reused even when fresh inference would exceed the current budget.

Longer recordings keep chunked transcription and a visible speaker-analysis limitation. Six-hour recording support is not six-hour speaker-analysis support. Existing recordings and reports remain readable. Greedy decoding and the existing `v4:` ASR identity remain unchanged; new reports explicitly record `asr_decoder: greedy`. Beam search was evaluated and rejected as the default after the longer pilot regressed. Experimental beam caches are kept separate from compatible greedy checkpoints. Speaker-cache identity is unchanged. Fast fully cached updates use an operation generation counter so identical terminal states cannot leave UI controls locked. No INTERNET permission was added. The APK uses the existing development signing key.

## Efficiency choices retained

The active laptop configuration already uses Sherpa-ONNX speaker models, CPU/int8 faster-whisper small and 120-second ASR chunks. Android already uses native Whisper chunks, ONNX speaker models and TF-IDF slide matching. These were verified rather than replaced again. Original recordings and durable chunk checkpoints remain on disk for playback and recovery; removing every WAV/intermediate file is not a safe drop-in optimization. Global speaker clustering still needs the waveform and is not a bounded-memory streaming diarizer.

NumPy and the optional semantic embedding path remain because existing inference/fusion callers use them. Selecting TF-IDF is available where lower-cost lexical matching is appropriate, but no unmeasured 70% RAM reduction or universal speed/accuracy improvement is claimed. This delivery focuses on avoiding incorrect decisions/evaluation results, safe memory limits, cached updates and optional OCR rather than a wholesale dependency rewrite.

## What remains before production/research claims

1. **Physical 6 GB Samsung testing.** The user supplied the RAM/device description, but no physical device was connected. Check capture/playback/imports, two-speaker and multi-speaker meetings, airplane-mode processing, locked-screen behavior, interruptions, thermal throttling, battery and storage handling. The emulator cannot establish those results.
2. **Natural Hindi/English/Hinglish recordings and labels.** The user confirmed none are available yet. Collect consented excerpts with independently checked transcripts and speaker/event/decision labels. Use the existing `scripts/evaluate_recordings.py` workflow. No target-domain accuracy can be measured, and no validated fine-tuning can be completed without these inputs.
3. **Real paired PPT/timing/influence labels.** Current fusion, lineage and influence remain transparent heuristic estimates. Evaluate the corrected baselines/ablations on the same labelled held-out meetings and report agreement/uncertainty. No learned influence model was trained or deployed in this delivery.
4. **Release qualification.** Use a production signing key and a tested Android background-processing policy before store distribution. Native image OCR, full visual chart understanding and unlimited-duration speaker inference are not implemented. Cloud processing is not required for the offline product and no cloud deployment was performed.
5. **Disk capacity.** About 2 GB remained free on the laptop during validation. Preserve user data/model caches and free appropriate disk space before accumulating more long recordings. No unrelated files or historical experiment artifacts were deleted to make these checks pass.

These are explicit remaining acceptance/research requirements, not completed stages. No new speech model, fine-tuning run or cloud service is needed to run the implemented local system. The [startup and device guide](../guides/RUN_CURRENT.md) contains current plain terminal commands.
